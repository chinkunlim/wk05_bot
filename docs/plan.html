一、專題緣起與目標

隨著大型語言模型（LLM）的普及，建置專屬智慧對話機器人已成為提升個人生產力與企業客服的核心手段。然而，現有許多教學範例常依賴 本機常駐（Local Node.js/Python）或付費雲端 VPS（AWS EC2、Heroku、Render），在實務運用中面臨伺服器維護成本高、公開 Webhook 容易遭惡意刷取 API 配額，以及問答紀錄不易留存分析等痛點。

本專題旨在實踐一套 100% 雲端原生 (Serverless)、零主機開銷 且 具備嚴密免費額度安全鎖 的 AI 對話機器人。第一版著眼於核心大腦與高可用通訊管道的落地實作，目前以 Telegram Bot 作為首發驗證平台，並已為第二版的 LINE Messaging API 雙軌整合打下強固基石。

專題三大核心宗旨：
  • 零伺服器成本（Zero Cost）：運用 Google Apps Script (GAS) 24/7 官方無伺服器架構，徹底擺脫主機費。
  • 免費額度絕對保護（Quota Safety First）：雙重檢驗（白名單 ID + 每日配額計數器），未授權者無法耗損 API。
  • 全軌跡數據留存（Container-Bound Audit）：自動於關聯之 Google Sheets 記錄每筆對話歷程、時間與 Token 用量。

二、系統架構設計與模組劃分

本系統採用微型無伺服器分層架構，所有程式碼均遵循 GAS V8 原生規範，禁止第三方 Node 依賴，確保無縫在瀏覽器雲端環境自主運行：

模組檔案 職責範圍 關鍵技術與設計亮點
src/Main.gs 請求分派與指令路由 Update ID 去重、白名單身分攔截、指令解析 (/start, /status, /reset)。
src/Gemini.gs Gemini API 串接與降級 支援 8192 Tokens、429 搜尋額度自動無感降級、動態注入當前台北真實時鐘基準。
src/Telegram.gs 通訊協定與排版處理 長文自動分段、Markdown 轉 Telegram 原生 HTML 轉換器、未閉合標籤自動修復補齊。
src/QuotaManager.gs 存取控制與配額計數 以 ScriptProperties 維護每日跨日重置計數器，精確落實每日上限保護。
src/Storage.gs 試算表日誌與短時記憶 使用 CacheService 保留最近 4 輪對話上下文 (20 分鐘)；即時寫入 Google Sheets。
src/Config.gs 環境變數與金鑰配置 禁止寫死金鑰；提供記憶體快取與動態模型名稱自訂 (GEMINI_MODEL)。

四、實測結果與避坑經驗總結

在開發與驗證過程中，我們如實記錄並克服了以下實測難題（相關截圖詳見開發紀錄網頁）：

  • 克服 Telegram Webhook 訊息狂發風暴：GAS 呼叫外部 API 耗時約 3 秒，Telegram 伺服器因未即時獲得 200 回應而反覆重試。我們實作了 update_id 短期快取去重機制，直接將重複請求於入口端濾除。
  • 排版渲染修復：Gemini 回覆長書單或條列內容時常帶有未支援的 Markdown 標籤，導致 Telegram API 報錯 can't parse entities。實作自製解析器與自動閉合標籤後，排版品質達到高質感呈現。
  • 破解 Google Search 429 配額陷阱與 2025 年時間認知：開啟 Search Grounding 時遭遇 Google 免費額度 429 拒絕，且模型因知識截斷將今年誤認作 2025 年。我們以「429 自動拔除工具重試」與「System Instruction 系統時鐘注入」雙管齊下，既不中斷對話，又能讓 AI 明確認知當前確切年份。

五、第一版待改善問題與第二版展望

  1. LINE Messaging API 實裝：第一版以 Telegram 建立起完整的配額防護與對話骨架，下一階段將在 Main.gs 加入 LINE 專屬 Webhook 解析與 Push/Reply 訊息路由，達成跨平台雙開。
  2. Google Sheets 自訂知識庫（RAG 檢索增強）：規劃在試算表中新增 FAQ 知識頁面，讓 Bot 在發送給 Gemini 前優先比對特定領域問答，打造專屬校園或專題助教。
  3. 付費版即時搜尋整合：評估綁定 Google Cloud Project 以解鎖官方 Grounding 搜尋額度，或串接無額度限制的公開新聞 API。
