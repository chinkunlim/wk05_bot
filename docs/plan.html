一、專題緣起、平台選擇與核心目標

隨著大型語言模型（LLM）的普及，建置專屬智慧對話機器人已成為提升個人生產力與企業客服的核心手段。然而，現有許多教學範例常依賴 本機常駐（Local Node.js/Python）或付費雲端 VPS（AWS EC2、Heroku、Render），在實務運用中面臨伺服器維護成本高、公開 Webhook 容易遭惡意刷取 API 配額，以及問答紀錄不易留存分析等痛點。

本專題旨在實踐一套 100% 雲端原生 (Serverless)、零主機開銷 且 具備嚴密免費額度安全鎖 的 AI 對話機器人。第一版著眼於核心大腦與高可用通訊管道的落地實作，目前以 Telegram Bot 作為首發驗證平台，並已為第二版的 LINE Messaging API 雙軌整合打下強固基石。

為什麼第一版優先選擇 Telegram Bot 而非 LINE Bot？
  • 長文支援度與原生 HTML 美化：Telegram 支援單則 4096 字元長訊息，並原生支援 HTML/Markdown 格式渲染，免除 LINE Flex Message 的繁瑣排版限制。
  • 原地動態更新體驗 (editMessageText)：Telegram 支援訊息原地編輯，使系統能在收到提問 0.5 秒內秒回「處理中/檢索中」，並在回答生成完畢後原地變身為完整回答，極致順暢且完全不洗版。
  • 零額外發送費用：無推送訊息每月則數計費壓力，最適合密集測試與學生免費用量。

二、系統架構設計與模組劃分

本系統採用微型無伺服器分層架構，所有程式碼均遵循 Google Apps Script (GAS) V8 原生規範，禁止第三方 Node 依賴，確保無縫在瀏覽器雲端環境自主運行：

模組檔案 職責範圍 關鍵技術與設計亮點
src/Main.gs 請求分派與路由 Update ID 去重、白名單身分攔截、0.5秒秒級狀態通知、全域錯誤透明回報。
src/WebSearch.gs 類 Grounding 檢索 Google News RSS 抓取、代名詞上下文補全、實體相關性校驗、階梯式降級搜尋。
src/Gemini.gs Gemini API 通訊 8192 Tokens 支援、429 自動無感降級、動態注入 2026 年台北真實時鐘基準。
src/Telegram.gs 通訊協定與排版 editMessageText 原地編輯、Markdown 轉 HTML、未閉合標籤自動補齊。
src/QuotaManager.gs 存取控制與配額計數 以 ScriptProperties 維護每日跨日重置計數器，精確落實每日上限保護。
src/Storage.gs 試算表日誌與短時記憶 使用 CacheService 保留最近 4 輪對話上下文 (20 分鐘)；即時寫入 Google Sheets。
src/Config.gs 環境變數與金鑰配置 禁止寫死金鑰；提供記憶體快取與動態模型名稱自訂 (GEMINI_MODEL)。

四、實測成果與避坑分析 (測試結果)

在開發與驗證過程中，我們如實記錄並克服了以下實測難題（相關截圖詳見開發紀錄網頁第 5 章）：

  • 2026 年亞運會最新成績檢索實證：執行 /search 2026 年台灣亞運會成績，成功突破 2025 年知識庫截斷限制，即時抓取最新新聞並列出未來商務、遠見雜誌等真實來源。
  • 東華大學陳文盛老師多輪實體消歧： 初次檢索時因東華大學同名同姓衝突，模型關聯至知名生科系榮譽教授；經過第 2、3 輪補充「通識中心、花蓮高中、資工系」後，AI 成功鎖定開授 Python 程式設計之兼任老師並準確回答排課。
  • 代詞追問與 Dcard 評價吻合： 第四次追問「這位老師在 Dcard 的評價是什麼？」，AI 成功調動深層校園語料庫，精確道出「上課溫柔、給分又甜又涼、對非科班友善」之真實學生心得。
  • 克服來源張冠李戴問題 (v1.9.2)： 實測中發現舊版在代詞追問時因缺乏主詞而搜出「兒童線上英語」等無關新聞，促使我們在最新版實裝「代名詞自動補全」與「實體相關性過濾」，無關來源一律剔除！

五、第一版待改善問題與第二版展望

  1. LINE Messaging API 雙軌整合：第一版以 Telegram 建立起完整的配額防護、類 Grounding 檢索與對話骨架，下一階段將在 Main.gs 加入 LINE 專屬 Webhook 解析 (X-Line-Signature) 與 Reply API，達成 LINE & Telegram 雙平台同時支援。
  2. 校園/內部知識庫自訂檢索 (RAG)：目前 Google News RSS 適合大眾時事新聞，但對大學特定冷門開課或行政規章資料命中率有限。第二版將在 Google 試算表建立 FAQ 分頁，實現校園/企業專屬 RAG 知識庫。
  3. 備用搜尋引擎介接：整合 DuckDuckGo Instant Answer 或維基百科 API 作為非新聞查詢之備用水庫。
