專題緣起與平臺決策
Project Background & Platform Decision

打破痛點與第一版平臺選型：為何優先 Telegram？

解決伺服器維護費、額度盜刷、回應黑箱痛點，並採取最利於即時互動的架構

痛點 1：主機成本與推播限制
傳統後端需租用常駐伺服器；LINE 免費帳號每月限制 200 則訊息，且不支援動態修改已發送訊息。

👉 第一版 Telegram 優先：
• GAS 24/7 免費代管，零主機費。
• Telegram 支援 editMessageText 原生動態文字替換，回饋零延遲。
痛點 2：LLM 額度盜刷風險
公開 Webhook 暴露在外，任一路人發訊皆會抽乾 Gemini API 免費額度。

👉 雙重安全護盾防禦：
• ALLOWED_USER_IDS 白名單嚴格攔截。
• QuotaManager 跨日自動歸零配額計數器，雙層保護用量。
痛點 3：免費版無法聯網與黑箱等待
Gemini 免費版內建 Google Search 配額為 0 (HTTP 429)；使用者發訊後無狀態提示，誤認當機。

👉 自研類 Grounding & 狀態回饋：
• GAS 自行抓取新聞 RSS 即時注入背景。
• Telegram 即時回傳「檢索中/思考中」提示。
第一版優先落地 Telegram，第二版規劃雙軌支援 LINE Messaging API

系統架構與技術棧
System Architecture

高可用無伺服器 (Serverless) 資料流

在 Google Cloud 全球骨幹網路上完成身分認證、即時檢索、狀態回饋與 LLM 推理

端到端資料流水線 (End-to-End Pipeline)
1. Webhook 入口防重擊：快取 update_id，阻絕 Telegram 逾時重發風暴。
2. 身分與配額攔截：比對白名單與當日計數，未授權用戶立即阻擋。
3. 發送動態佔位訊息：立即發送 ⏳ 收到您的問題... 並取得 message_id。
4. Serverless 類 Grounding：呼叫 WebSearch.gs 抓取 Google News RSS，並更新狀態為 🔍 正在檢索...。
5. 消歧義與上下文組裝：解析指代名詞，拼接短期對話記憶 (CacheService)。
6. Gemini 2.5 推論與就地替換：推論完成後透過 editTelegramMessage 將佔位訊息平滑更新為完整答案與來源。
7. 試算表記錄：寫入 Google Sheets 完整留存時間戳、Prompt 與 Token 消耗。
核心模組職責矩陣 (Module Matrix)
• Main.gs：Webhook 路由、漸進式狀態更新流水線、透明錯誤回報。
• WebSearch.gs：Serverless 即時搜尋引擎、代名詞消歧義、無關來源過濾。
• Telegram.gs：長文分段、HTML 自動閉合修復、editTelegramMessage 原生支援。
• Gemini.gs：REST 通訊、8192 Token、429 無感降級、時序注入、檢索上下文注入。
• QuotaManager.gs：白名單過濾、每日限額跨日重置。
• Storage.gs：多輪對話快取序列化、Google Sheets 稽核日誌記錄。

核心突破 (一)
Progressive UX & Error Transparency

即時動態狀態回饋與透明除錯機制

徹底告別黑箱等待；使用者發訊後立即可知 Bot 當前運作進度

1. Telegram 原生動態狀態看板
使用者痛點： 傳統 Bot 發送後無任何反應，使用者不清楚是否成功送出，產生焦慮甚至重複按送出。

解決方案 (v1.8.0 / v1.9.0)：
• 階段一 (即時接收)： 發送 ⏳ 收到您的問題，正在為您處理中...
• 階段二 (即時檢索)： 替換為 🔍 正在檢索即時新聞與公開資料...
• 階段三 (深度分析)： 替換為 🧠 正在深度分析並為您整理完整回答...
• 階段四 (完美呈現)： 原地平滑更新為完整答案，對話框乾淨不灌水！
2. 全局透明錯誤報警機制
使用者痛點： 腳本出錯時後台靜默失敗或只印日誌，前端毫無反饋。

解決方案 (v1.9.1)：
• 在 Main.gs 頂層 try...catch 中加入真實錯誤字串傳遞。
• 若發生未定義變數或 API 異常，Telegram 直接顯示具體錯誤訊息（如 ReferenceError: env is not defined）。
• 效益： 開發者可立即截圖除錯，數分鐘內精準修復變數作用域問題。

核心突破 (二)
Serverless Web Search & Context Injection

突破免費限制：GAS 類 Grounding 檢索與消歧義

維持 100% 免費架構，達成即時時事獲取、多輪指代代名詞消歧義與精準資料源過濾

1. Serverless 類 Grounding
• Google AI Studio 免費帳號之 Search 配額為 0。
• 改由 GAS 內 UrlFetchApp 針對 Google News RSS 抓取即時新聞 XML。
• 過濾標籤保留核心摘要，將精簡資料拼裝為 Prompt 背景注入 Gemini。
2. 指代代名詞消歧義擴展
• 痛點： 用戶追問「這位老師在 Dcard 評價？」，搜尋字詞缺少主詞導致檢索失準。
• 解決方案 (v1.9.2)： 內建 expandQueryWithContext()，自動從對話快取提取主體名詞，重構檢索詞為「東華大學 陳文盛 Dcard 評價」。
3. 相關性來源過濾機制
• 痛點： 搜尋結果有時包含不相關新聞（如銘傳大學、兒童英語），盲目引用造成誤導。
• 解決方案 (v1.9.2)： filterRelevantArticles() 嚴格驗證實體關鍵字，未命中者全數剔除；若無相關結果則隱藏來源區塊。

關鍵實測個案剖析
Case Study & Multi-turn Convergence

真實提問案例剖析：為什麼越問越精準？

以「杭州亞運金牌檢索」與「東華大學陳文盛老師」為例，揭示 LLM 多輪知識收斂機制

個案一：時事檢索 (杭州亞運金牌數)
• 提問：「台灣在杭州亞運獲得多少面金牌？」
• 執行歷程： Bot 即時觸發 WebSearch.gs 檢索亞運相關報導。
• 實測結果： 成功精確回覆「19面金牌、20面銀牌、28面銅牌，總計67面獎牌，追平隊史最佳紀錄」，並附上相關時事參考來源。
• 意義： 驗證 GAS 類 Grounding 具備突破 LLM 知識截斷之即時資訊獲取能力。
個案二：同名實體消歧義 (東華大學陳文盛老師)
• 問題根源： 東華大學有兩位「陳文盛」：(1) 生命科學系退休榮譽教授 (著作豐富)；(2) 通識教育中心兼任講師 (花蓮高中資訊教師，教授 Python)。
• 輪次一 (偏差)： 單靠模型預訓練記憶，直覺回答生科系教授。
• 輪次二 (無解)： 輸入純敘述句且帶標點符號，RSS 檢索無結果。
• 輪次三 & 四 (收斂)： 使用者補充「通識、資工、花中」，Bot 多輪記憶疊加消歧義，精準鎖定授課 Python 的陳老師！

第一版待改善問題與展望
Current Status & Phase 2 Roadmap

第一版現況檢視與第二版 (Phase 2) 擴充藍圖

誠實反映現階段架構限制，確立後續功能演進方向

1. LINE Messaging API 雙軌接軌
現狀： 第一版因訊息費用與動態看板考量，優先完成 Telegram Bot 部署。

第二版規劃： 新增 LINE Webhook 簽章驗證與 Reply API，共用 Gemini、快取與試算表核心模組，達成雙平臺服務覆蓋。
2. 試算表自訂知識庫 (RAG)
現狀： Google Sheets 目前主要作為全軌跡日誌與 Token 消耗稽核庫。

第二版規劃： 新增「FAQ 知識庫」分頁，透過語意相似度或關鍵字在提問前優先檢索專屬試算表，打造校園/企業專屬助理。
3. 多元即時搜尋引擎串接
現狀： 採用 Google News RSS 類 Grounding，在即時時事表現優異，但小眾論壇 (如 Dcard) 涵蓋較受限。

第二版規劃： 串接 Tavily、Serper 或 Google Custom Search API，進一步強化校園與特定論壇資料檢索廣度。
