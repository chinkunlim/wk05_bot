核心功能與對話架構
Serverless 24/7 零成本設計
四大核心功能模組與全流程運作機制
整合 Google 雲端原生免費生態系，達成零常駐伺服器、高安全防護與即時新聞檢索之閉環。
1. 雙重額度安全防護
• 嚴格白名單 (ALLOWED_USER_IDS) 阻擋未授權存取。
• 當日計數器 (MAX_DAILY_REQUESTS) 防止 API 費用超支。
• 429 頻率超限自動冷卻 2.5 秒重試，保障服務不中斷。
2. 雲端原生類 Grounding
• GAS 直接抓取 Google News RSS 即時新聞。
• 支援代名詞上下文消歧補全 (Coreference Resolution)。
• 突破 LLM 靜態訓練資料截止時間限制，並附可點擊來源。
3. 秒級原地狀態反饋
• 收到問題 0.5 秒內發送動態狀態提示。
• editMessageText 原地即時變更：檢索中 → 思考中 → 最終解答。
• 動態顯示取得篇數，乾淨不洗版，消滅盲等痛點。
4. 全對話軌跡日誌
• Google 試算表自動寫入時間、提問者、問題與解答。
• 精確統計 Prompt / Completion / Total Tokens。
• 內建 CacheService 短期記憶（保留 4 輪對話）。
對話範例流： 使用者輸入「/search 台灣最新新聞」 → 機器人 0.5 秒內秒回「收到提問，正在為您檢索即時資料中...」 → 原地更新為「即時資料檢索完成（成功獲取 4 篇最新相關資訊），正在分析彙整回答...」 → 原地轉化為條列式重點新聞、摘要與 4 則超連結來源！
架構：GAS Webhook → QuotaManager → WebSearch → Gemini API → Telegram API

改善成果與實測驗證
作業關鍵四大要素落實
課後改善版 (v1.9.5) 關鍵突破與三項情境測試
記錄「原本問題 → 修改內容 → 前後差異 → 重新測試結果」，並完整親測三種情境。
四大改善要素記錄
• 原本問題： 提問複合詞「台灣亞運會」時，爬蟲抓到 8 篇新聞卻因過濾器硬匹配完整 5 字而全數被誤判為無效噪音丟棄 (0 篇)，AI 只能無奈回覆「無法連網檢索」。
• 修改內容： 重構 WebSearch.gs，導入地域前綴剝除與 2-gram 核心詞素萃取；Main.gs 新增動態篇數反饋；Gemini.gs 實作 429 退避與 404/503 自動備援。
• 前後差異： 複合詞命中率由 0% 飆升至 100% (8 篇全數通過)；AI 精確回覆「55 面獎牌 (5金17銀33銅)」並附來源；徹底杜絕 429 頻率限速報錯。
• 重測結果： 如下表三項情境，各項預期與實際表現均 100% 通過驗證！

AI 協作與審查經驗
深度反思與人機協同
AI 如何協助開發，以及我們如何審查與修正 AI 產出
真實記錄開發過程中的人機互動、代表性提示詞，以及發現並修復 AI 盲點的寶貴經驗。
1. 使用的 AI 工具
• 開發環境： Google Antigravity Agentic IDE。
• 基礎模型： Google Gemini 2.5 / 3.5 / 3.6 Flash 系列。
• 執行環境： Google Apps Script (V8 Runtime) + Node.js 本機語法沙盒檢驗。
2. 代表性提示詞指令
• 通用性要求：「會隨機提問，所以不要根據我的問題 hardcoded。」（確保開放式領域穩健性）
• 敏銳除錯質疑：「第一張截圖是用 3.6，第二張是用 3.5，都顯示沒有 search 功能。我們之前使用爬蟲去找丟給 gemini，現在還是嗎？」（直接命中問題根源）
3. 檢查或修正 AI 產出經驗
• 抓出過濾器誤殺盲點： 當使用者提出上述質疑時，AI 原先以為是模型切換問題。經使用者提醒並深入執行單元測試後，發現 AI 先前編寫的相關性過濾器存在「僵化完整字串匹配」缺陷，導致 8 篇有效新聞被 100% 誤殺為 0 篇！
• 成功引導重構： 由開發者引導 AI 放寬召回率，改採 2-gram 雙字詞素抽取與前綴剝除，一舉將命中率修復回 100%。
人機協同體會： AI 在代碼生成上速度極快，但在多語系斷詞與邊界條件（如中文專有名詞縮寫慣例）上容易陷入「過度嚴格過濾」的盲點。人類開發者保持敏銳的邏輯質疑、以真實場景截圖反饋，並進行代碼級追蹤，是打造高可靠性 AI 系統不可或缺的關鍵。
AI 協作亮點：保留所有 Git 歷程，真實記錄人機互動與問題修復歷程
